# Протокол настройки по BLE, версия 1

Как веб-страница `web/index.html` разговаривает с пультом в режиме настройки (`openspec/changes/add-remote-config`).
Источник истины для прошивки (`firmware/src/settings.h`, BLE-сервис) и страницы. Меняется формат —
меняется `version` блока и этот документ.

## Где доступен

Только в режиме настройки: обе кнопки удерживаются ≥ 4 с. Вне режима радио выключено.

- Имя в рекламе: `IR-Remote-XXXX`, XXXX — последние 4 hex-цифры BLE-адреса устройства, заглавными.
- В рекламе — 128-битный UUID сервиса, по нему страница фильтрует устройства.
- Без сопряжения и пароля: окно открывается только физическим удержанием кнопок.
- Пульт выключается, если 60 с не было ни одной команды: любое чтение или запись любой характеристики
  (не только `ping`) начинает отсчёт заново.

## UUID

Сгенерированы 26.11.2026 одним `uuidgen`; характеристики отличаются от сервиса первой группой.

| Что | UUID | Свойства |
|---|---|---|
| Сервис | `d5e80001-b2f6-4b31-98c6-7923e11860fc` | — |
| `config` | `d5e80002-b2f6-4b31-98c6-7923e11860fc` | read, write (с ответом) |
| `status` | `d5e80003-b2f6-4b31-98c6-7923e11860fc` | read |
| `ping` | `d5e80004-b2f6-4b31-98c6-7923e11860fc` | write, write without response |
| `test` | `d5e80005-b2f6-4b31-98c6-7923e11860fc` | write (с ответом) |

## Блок настроек v1 (`config`), 11 байт, little-endian

| Смещение | Поле | Тип | Значения |
|---|---|---|---|
| 0 | `version` | u8 | `1` |
| 1 | `a.flags` | u8 | бит 0 — кнопке назначен код; бит 1 — 16-битный адрес (extended NEC); биты 2–7 — `0` |
| 2 | `a.address` | u16 | 8-битный адрес: `0x00`–`0xFF`; 16-битный: `0x0000`–`0xFFFF` |
| 4 | `a.command` | u8 | `0x00`–`0xFF` |
| 5 | `b.flags` | u8 | как у A |
| 6 | `b.address` | u16 | как у A |
| 8 | `b.command` | u8 | как у A |
| 9 | `repeat_hz` | u8 | кадров в секунду при удержании, `1`–`10` |
| 10 | `repeat_mode` | u8 | `0` — полный кадр, `1` — код повтора NEC |

Значения по умолчанию (чистый пульт, во флеше нет целого блока): обе кнопки не назначены
(`flags = 0`, адрес и команда `0`), `repeat_hz = 3`, `repeat_mode = 0`. Ненастроенная кнопка не излучает,
пульт медленно мигает индикатором 3 раза (500/500 мс) и выключается.

Пример: A = адрес `0x32`, команда `0x02`; B = `0x32` / `0x03`; 3 кадра/с, полный кадр:

```
01  01 32 00 02  01 32 00 03  03 00
```

8-битный адрес передаётся в младшем байте `address`, старший — `0`. Кадр NEC из него: `адрес, ~адрес,
команда, ~команда`. Для 16-битного адреса: `адрес_мл, адрес_ст, команда, ~команда`.

### Чтение `config`
Возвращает текущий рабочий блок — сохранённый во флеше или значения по умолчанию.

### Запись `config`
Записывается весь блок одной операцией (11 байт). Пульт проверяет блок, сохраняет его во флеш и только
после успешной записи отвечает «успех». Неверный блок отклоняется ATT-ошибкой приложения (ниже), сохранённые
настройки не меняются.

## `status`, 6 байт, little-endian

| Смещение | Поле | Тип | Что |
|---|---|---|---|
| 0 | `proto` | u8 | версия этого протокола, `1` |
| 1 | `fw_major` | u8 | версия прошивки |
| 2 | `fw_minor` | u8 | |
| 3 | `fw_patch` | u8 | |
| 4 | `battery_mv` | u16 | напряжение питания МК в мВ, замер при входе в режим настройки, до включения радио |

Страница показывает напряжение в вольтах: `battery_mv / 1000`. Замер — внутренний канал VBAT АЦП при усилении
−12 дБ: `V = (АЦП / 512 − 3) × 1,05 В`. Формула сверена с порогами WCH в
`Application/PDF_DataLogger/CH592_PDF_Logger_BLE/HAL/include/BAT.h` (2755 → 2,5 В, 2706 → 2,4 В, 2658 → 2,3 В,
2024 → 1,0 В); точность на плате не проверена.

## `ping`

Запись любых данных (страница шлёт 1 байт `0x00`) — только продлевает режим на 60 с. Страница пингует раз в 30 с.

## `test`

Излучает один кадр NEC кнопки A или B. Ничего не сохраняет.

| Длина | Содержимое | Каким кодом |
|---|---|---|
| 1 байт | `button` u8: `0` — A, `1` — B | текущим рабочим блоком |
| 12 байт | `button` u8 + блок v1 (11 байт) | кодом из переданного блока — так проверяется ещё не сохранённый код |

Блок в `test` проверяется теми же правилами, что и в `config`. Пока излучается предыдущий кадр, новый `test`
пропускается (ответ — успех).

## Ошибки (ATT Application Error)

Пульт отвечает двумя кодами; точную причину страница называет сама — она проверяет значения до отправки.

| Код | Имя | Когда |
|---|---|---|
| `0x80` | `ERR_INVALID` | неверные данные: не та длина (`config` ≠ 11, `test` ≠ 1 и ≠ 12), `version` ≠ 1, лишние биты `flags`, адрес > `0xFF` без флага 16 бит, `repeat_hz` вне `1`–`10`, `repeat_mode` не `0`/`1`, `test`: кнопка не `0`/`1` или ей не назначен код |
| `0x81` | `ERR_FLASH` | `config`: стирание или запись флеша вернули ошибку |

У неназначенной кнопки (бит 0 = 0) адрес и команда не проверяются.

## Хранение во флеше (DataFlash CH592)

Одна запись в начале DataFlash (смещение `0x0000`, `EEPROM_READ/WRITE/ERASE` SDK). Стирается весь блок 4 КБ, а не
страница 256 байт: в `ISP592.h` для чипа с ID `DEF_CHIP_ID_CH592A` (QFN-28) стирание не кратно 4 КБ уходит в вечный
цикл; наш CH592F тоже QFN-28, какой у него ID — не проверено. `StartAddr` в `EEPROM_*` — смещение от начала
DataFlash (`0x70000`): так задан адрес хранилища BLE в `CONFIG.h` SDK (`BLE_SNV_ADDR = 0x77000 − FLASH_ROM_MAX_SIZE`).
Запись, 13 байт:

| Смещение | Поле | Тип |
|---|---|---|
| 0 | блок v1 | 11 байт |
| 11 | `crc` | u16, CRC-16/CCITT-FALSE (полином `0x1021`, начальное `0xFFFF`) по байтам 0–10 |

- **Запись:** стереть блок 4 КБ → записать 13 байт. Ошибка SDK — `ERR_FLASH`; чтением не сверяем (принцип простоты).
- **Чтение при старте:** запись годна, если CRC совпала и блок проходит проверку; иначе — значения по умолчанию
  (чистый пульт).
- **Прерванная запись** (батарейку вынули): CRC не сходится — пульт стартует ненастроенным, его настраивают заново.
  Мусорные или смешанные коды он не излучает никогда. Решение владельца 26.11.2026: вторая копия не нужна.
- Хранилище BLE-библиотеки (SNV) по умолчанию — смещение `0x7000`, с записью настроек не пересекается; в прошивке оно
  выключено (`BLE_SNV=0`): сопряжения нет, хранить нечего.
