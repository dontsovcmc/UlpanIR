# Стенд UlpanIR (ESP32-C6 Super Mini)

Стенд шьёт CH592F на плате пульта по 2-проводной отладке WCH (RVSWD) через гребёнку J1 и проверяет плату:
- нажимает кнопки, замыкая узлы на землю;
- принимает ИК;
- смотрит напряжение после ключа;
- читает лог пульта;
- говорит с пультом по BLE.

Решения и требования — `openspec/changes/add-test-stand/` (design, specs `stand-port`, `stand-flash`, `stand-test`).
Образцы — `waterius/waterius_flasher` (C6, команды `#…`) и `waterius/jaffa_flasher` (свой SWD, лог в тот же
порт).

**Не проверено на железе:** Super Mini и плат пока нет. Всё, что можно, проверено тестами на Mac; что проверить на
плате — `board-checks.md`.

## Проводка

Эта таблица — источник правды для `src/pins.h`. Провода идут напрямую, без резисторов, батарейку из пульта
вынуть.

| Super Mini | J1 | Цепь | Роль |
|---|---|---|---|
| GPIO1 | 3 | BTNA_N | кнопка A: только 0 или вход |
| GPIO2 | 1 | BTNB_N | кнопка B: только 0 или вход |
| GPIO18 | 7 | SWCLK (PB15) | выход только во время сеанса отладки |
| GPIO19 | 6 | SWDIO (PB14) | вход/выход, встроенная подтяжка только во время сеанса |
| GPIO4 | 8 | TX пульта (PA9) | приём лога UART1 115200 8N1, без подтяжки |
| GPIO0 | 5 | VBAT_SW | АЦП, признак «включён»; встроенная подтяжка к земле разряжает C4 |
| GPIO3 | — | выход ИК-приёмника | RMT RX |
| 3V3 | 2 | VBAT | питание платы; ИК-приёмник — тоже от 3V3 |
| GND | 4 | GND | общий; земля ИК-приёмника |

- J1.9 (RX пульта) не подключается.
- J1.5 к 3V3 не подключать: иначе выключение не увидеть.
- Не заняты (и не занимать):
  - GPIO8, GPIO9, GPIO15 — стяжки и светодиоды Super Mini;
  - GPIO12, GPIO13 — USB;
  - GPIO16, GPIO17 — UART0; GPIO16 с самого сброса держит 1.
- ИК-приёмник 38 кГц (VS1838B / TSOP38238): выход на GPIO3, питание 3V3. Ставится напротив торца платы с LED1 и
  LED2, в 10–30 см.

Вне команд все линии к J1 — вход без подтяжки. Кнопки стенд выводит только в 0, SWDIO и SWCLK — только во время
`#chip`, `#flash`, `#erase`. Так выключенный пульт не подпитывается через выводы МК, и выключение видно по VBAT_SW.

## Команды

Строка `#<имя> [аргументы]\n`, не длиннее 64 байт. Ответ — строки `# …\n`, всегда с новой строки. Всё остальное в
порту — лог пульта с J1.8 как есть. Команды выполняются по одной; пришедшие во время `#press` ждут в очереди.

| Команда | Ответ | Что делает |
|---|---|---|
| `#info` | `# ulpanir_stand 0.1.0 uptime=<с>` | версия и время работы |
| `#heap` | `# heap: max=<байт> free=<байт>` | куча C6: хватит ли на образ 256 КБ (задача 8.1) |
| `#press <a\|b\|ab> <1–10000>` | `# press: a 100` после отпускания | держать узлы в 0; `ab` — одной записью в регистр |
| `#lines off` | `# lines: отпущены` | отпустить всё; посреди `#press` прерывает нажатие, тогда ответа `press:` нет |
| `#power` | `# power: вкл 3.28 В` / `выкл 0.04 В` | VBAT_SW; порог 1,5 В — гипотеза, подобрать на плате |
| `#ir on` / `#ir off` | `# ir: вкл` / `# ir: выкл` | между ними — строки кадров, `t=` в мс от `#ir on` |
| — | `# ir: nec 0x32 0x02 t=…` | кадр NEC; адрес из 4 hex-цифр — 16-битный |
| — | `# ir: повтор t=…`, `# ir: неразобрано <меток> t=…` | код повтора NEC и всё прочее |
| `#chip` | `# chip: CH59x uid=<16 hex>` | тип чипа и UID, затем перезапуск |
| `#flash <длина> <crc32>` + байты | `# flash: записано <n> байт за <мс> мс` | образ с адреса 0; crc32 — как `zlib.crc32`, 8 hex |
| `#erase data` | `# erase: настройки стёрты` | вся DataFlash (0x70000, 32 КБ); основная flash не трогается |
| `#ble connect [мс]` | `# ble: подключён IR-Remote-… rssi=<дБм>` / `# ble: не найден` | по умолчанию ищет 10 с |
| `#ble read <config\|status>` | `# ble: config <hex>` | |
| `#ble write <config\|ping\|test> <hex>` | `# ble: записано config` / `отклонено config` | запись с ответом |
| `#ble close` | `# ble: отключён` | |

На время `#chip`, `#flash`, `#erase` стенд держит узел A в 0: ключ Q1 открыт, МК питается. После перезапуска
узел A сразу отпускается, пульт выключается сам.

Ошибки:

- **Общие:**
  - `# неизвестная команда: <имя>`;
  - `# слишком длинная команда`.
- **`#flash`, до касания чипа:**
  - `неверная длина: <слово>` (1–262144);
  - `неверный crc32: <слово>`;
  - `обрыв приёма` (байты не приходили 2 с);
  - `crc32 не сходится`;
  - `нет памяти: <n> байт` (пришедшие байты образа стенд выбрасывает).
- **`#flash`, после касания чипа:**
  - `нет ответа чипа`;
  - `не CH59x: <семейство>`;
  - `сверка не сошлась 0x<адрес>` (адрес начала блока 256 байт).
- **`#chip`:**
  - `# chip: нет ответа`;
  - `# chip: не CH59x: <семейство>`.
- **`#erase`:**
  - `# erase: неизвестная область: <слово>`;
  - `нет ответа чипа`;
  - `не CH59x: <семейство>`.
- **`#press`:**
  - `неизвестная кнопка: <слово>`;
  - `неизвестная длительность: <слово>`.
- **`#ble`:**
  - `нет подключения`;
  - `неизвестная длительность` (1–60000);
  - `неизвестная характеристика`;
  - `неверные данные` (hex чётной длины, до 24 байт);
  - `неизвестная команда`.
- **`#ir` и `#lines`:** `неизвестный режим: <слово>`.

Строк `#heap`, `нет памяти`, `не CH59x` у `#flash` и `#erase`, ошибок разбора у `#ble`, `#ir` и `#lines` в спеках нет.
Они добавлены при реализации.

## Скрипт на Mac

```sh
uv run stand/host/stand.py [--port P] [-v] flash firmware/build/ulpanir/remote.bin   # только прошить
uv run stand/host/stand.py test           # проверить прошитую плату (настройки стираются)
uv run stand/host/stand.py run <bin>      # прошить, стереть настройки, проверить — то же, что make stand
uv run stand/host/stand.py monitor '#info'   # вывести порт как есть
```

- **Порт** по умолчанию — первый `/dev/cu.usbmodem*` с VID Espressif `0x303A`. Скрипт открывает его с RTS=0 и
  DTR=0.
- **Сценарий** — 10 проверок спеки `stand-test`, около 1,5 мин (режим настройки гаснет через 60 с).
- **Итог:**
  - `ГОДНА`, код возврата 0;
  - `БРАК: <номера>`, код возврата 1.
- **Протокол** пишется в `stand/reports/<дата>_<время>_<uid>.txt`.
- Если не прошли проверки 1 или 2, остальные помечаются «не проводилась».

Из `firmware/`: `make stand-flash`, `make stand`.

## Сборка и прошивка самого стенда

PlatformIO (`~/.platformio/penv/bin/pio`), платформа pioarduino 55.03.312-1 (ядро Arduino-ESP32 3.3.12), как у
waterius_flasher.

```sh
cd stand
pio test -e native            # тесты core/ на Mac
pio run -e esp32c6            # сборка
pio run -e esp32c6 -t upload  # прошить Super Mini по USB; если не входит в загрузчик — держать BOOT при подключении
uv run --with pytest --with pyserial pytest host   # тест скрипта на поддельном стенде
```

## Как устроено

- **`src/core/`** — чистый C++ без Arduino, тесты в `test/` (Unity, env `native`) на поддельном железе
  (`test/fakes/fakes.h`).
  - `console` — один поток: лог как есть, строки `# …` с новой строки, под мьютексом;
  - `reader` — строки команд и сырые байты образа из одного входа;
  - `stand` — команды;
  - `nec_rx` — разбор ИК с допуском ±25 % (тест гоняет кодировщик пульта `firmware/src/nec.c`);
  - `crc32`.
- **`src/port/`** — железо C6:
  - линии GPIO;
  - АЦП;
  - UART1;
  - RMT;
  - BLE-клиент ядра (на C6 — NimBLE);
  - RVSWD.
- **Отладка** — ch32fun funprog (`vendor/ch32fun/`, MIT, снимок с коммитом в `VERSION`).
  - Свои у стенда: настройки, задержки и биты RVSWD регистрами GPIO C6 (`port/bitbang_rvswd_c6.h`, по образцу ESP32-S2
    из `cnlohr/esp32s2-cookbook`).
  - Запись — блобом в ОЗУ МК, как у minichlink с программатором funprog.
  - Сверка — встроенной командой контроллера flash, по блокам 256 байт.
- **Задачи FreeRTOS:**
  - «команды» — `loop()`, блокируется на `#press`, `#flash`, `#ble`;
  - «поток» — лог UART1 и ИК-кадры в порт.

## Гипотезы (проверяются на плате, `board-checks.md`)

- **RVSWD:** полупериоды RVSWD 0,25/0,5/2 мкс подходят CH592. Если нет — увеличить в `SetProtocolSpeed`
  (`port/bitbang_rvswd_c6.h`).
- **Питание при сеансе:** после нажатия A МК стартует за 50 мс (`SESSION_POWER_MS`).
- **Куча:** её больше 300 КБ одним куском, проверяется `#heap`. После первого `#ble connect` стек BLE остаётся в
  памяти.
- **Подтяжки:**
  - встроенная подтяжка GPIO0 к земле около 45 кОм, разряд C4 до 1,5 В — около 0,8 с;
  - порог `#power` — 1,5 В.
- **ИК:**
  - RMT ядра отдаёт целый кадр NEC одним чтением;
  - аппаратный фильтр RMT — не длиннее примерно 3 мкс, помехи до 100 мкс склеивает `core::ir_filter`.
- **BLE:**
  - BLE central ядра работает на C6;
  - пульт в рекламе даёт UUID сервиса; имя может прийти в ответе на сканирование. Стенд ищет по UUID, имя
    `IR-Remote-` сверяет, если оно есть.
- **Выход линий:** выбор сигнала 128 в матрице GPIO даёт выход «бит GPIO_OUT_REG, включение — бит GPIO_ENABLE_REG»,
  без мелькания уровня при настройке.
