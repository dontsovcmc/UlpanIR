# Страница настройки пульта

`index.html` + `protocol.js` — статическая страница без сборки: Web Bluetooth в Chrome и Edge
(Windows, macOS, Linux, Android). Протокол — `docs/ble_protocol.md`, требования —
`openspec/changes/add-remote-config/specs/remote-config/spec.md`.

| Файл | Что |
|---|---|
| `index.html` | интерфейс: подключение, форма, предпросмотр, запись, проверка кода, пинг и окно долгой сессии |
| `protocol.js` | логика без DOM и Bluetooth: UUID, блок настроек, проверки (те же, что в прошивке), тексты ошибок, таймеры сессии |
| `test/protocol.test.mjs` | тесты логики: `node --test web/test/protocol.test.mjs` |

Отступление от design.md («один HTML»): логика вынесена во второй статический файл, чтобы её проверять тестами.
Сборки по-прежнему нет.

## Как пользоваться

1. Зажать обе кнопки пульта на 4 с — индикатор мигает.
2. «Подключить» → выбрать `IR-Remote-XXXX`. Страница читает коды, версию прошивки и напряжение батарейки.
3. Ввести коды (hex), частоту и вид повтора. Под кнопками — байты кадра NEC, ниже — блок настроек как он уйдёт в пульт.
4. «Отправить код A/B» — пульт излучает кадр с кодом из формы, даже не сохранённым.
5. «Записать» → «Сохранено». Неверные значения страница не отправляет и называет ошибку.

Пока страница подключена, она раз в 30 с шлёт пинг. Через 9 мин спрашивает «Пульт отключится через 60 с»:
«Продолжить» — ещё 9 мин, «Отключить» или нет ответа 60 с — отключение; пульт выключится сам через 60 с после
последней команды.

`?fast` в адресе — ускоренные таймеры для проверки окна: пинг 3 с, окно через 9 с, ответ 6 с.

## Запуск локально

Web Bluetooth работает только в защищённом контексте: HTTPS или `localhost`.

```sh
cd web && python3 -m http.server 8000 --bind 127.0.0.1   # открыть http://127.0.0.1:8000/ в Chrome
```

## Публикация

**https://dontsovcmc.github.io/UlpanIR/** — GitHub Pages, публикует сценарий `.github/workflows/pages.yml` при каждом
push в `main`, затрагивающем `web/`: сначала тесты логики, потом публикация каталога `web/`.

## Что проверено и что нет (26.11.2026)

- Проверено: опубликованная страница открывается по HTTPS в Chrome на macOS, Web Bluetooth доступен; в Chrome (macOS) «Подключить» активна, в Firefox — сообщение «Браузер не поддерживает Web Bluetooth —
  откройте в Chrome или Edge», кнопка неактивна; предпросмотр и проверки формы (пример протокола даёт
  `01 01 32 00 02 01 32 00 03 03 00`, кадр A — `32 CD 02 FD`, частота 50 не отправляется); тесты логики.
- Не проверено: подключение к пульту, чтение, запись, тест-кадр, пинг и окно — нужен пульт или отладочная плата
  с прошивкой. Гипотеза: Chrome не передаёт странице код ATT-ошибки приложения (0x80, 0x81), поэтому страница
  проверяет значения сама до отправки, а отказ пульта показывает общим текстом.
