# Design

## Context

ИК-модуль готов в `add-ir-nec-transmit` (коды — константы). Требования — `specs/remote-config/spec.md`.

## Goals / Non-Goals

**Goals:**
- Настройка с ноутбука и Android-телефона в Chrome, отлаженная на DK.

**Non-Goals:**
- Сопряжение BLE и пароль: окно открывается только физическим удержанием двух кнопок.
- OTA-обновление прошивки.

## Decisions

### Настройки: один блок в NVS
Одна запись фиксированного формата с версией и CRC; NVS пишет атомарно, поэтому прерванная запись оставляет прежний блок целиком. Альтернатива — запись на поле: проще менять, но теряется атомарность.

Формат блока v1 (little-endian): `version u8`; для A и B: `flags u8` (бит 0 — назначено, бит 1 — 16-битный адрес), `address u16`, `command u8`; затем `repeat_hz u8` (1–10), `repeat_mode u8` (0 — полный кадр, 1 — NEC-повтор).

### BLE: свой GATT-сервис
128-битный сервис: `config` (чтение/запись блока целиком; ошибка валидации — ATT-код приложения), `status` (чтение: версия прошивки, мВ батарейки), `test` (запись: 0 — A, 1 — B, текущим кодом из последнего записанного или переданного блока). UUID генерируются один раз и фиксируются в `docs/ble_protocol.md`. Альтернатива — Nordic UART с текстовыми командами: нужен парсер и свой протокол.

Имя в рекламе — «IR-Remote-XXXX», XXXX — последние 4 hex-цифры адреса.

### Страница: один статический HTML без сборки
Встроенный JS, публикация на GitHub Pages. Поля: hex-адрес, галка 16 бит, hex-команда, частота, вид повтора; предпросмотр байтов кадра; кнопки «Подключить», «Прочитать», «Записать», «Отправить A/B». Альтернатива — фреймворк со сборкой: лишний для одной формы.

## Risks / Trade-offs

- [Web Bluetooth на macOS/Android ведёт себя по-разному при переподключении] → проверка на обеих платформах в задачах.
- [Кто-то рядом перепишет коды за 60 с окна] → принято: нужен физический доступ к пульту.
