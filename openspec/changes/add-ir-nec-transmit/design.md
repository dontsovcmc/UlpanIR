# Design

## Context

Исходные материалы — в корне репозитория (`README.md`, `schematic.*`, `sim*.py`). Кода нет. У Nordic нет dev-kit именно для nRF52810 — используется nRF52 DK с эмуляцией (`nrf52dk/nrf52810`). Требования — `specs/ir-transmit/spec.md`.

## Goals / Non-Goals

**Goals:**
- Модуль NEC, покрытый unit-тестами без железа, и проверенный приборами вывод на DK.

**Non-Goals:**
- Хранение настроек, BLE, управление питанием, своя плата — это следующие задачи.
- Протоколы кроме NEC.

## Decisions

### Прошивка: nRF Connect SDK / Zephyr
Цель `nrf52dk/nrf52810` даёт отладку на DK, а BLE и NVS понадобятся в следующей задаче. Альтернатива — голый nrfx: меньше кода, но BLE и флеш пришлось бы делать руками.

### Кодирование отдельно от вывода
Чистая функция «адрес, команда, тип кадра → массив длительностей импульс/пауза» тестируется ztest на `native_sim`. Вывод — отдельный модуль. Так тайминги проверяются тестом, а не только осциллографом.

### Вывод: PWM-последовательность через EasyDMA
Несущая 38 кГц, скважность 1/3 — аппаратный PWM; огибающая NEC — последовательность значений PWM (0 % / 33 %) без участия ЦП. Альтернатива — переключать GPIO по таймеру: проще, но джиттер от BLE-прерываний, когда в следующей задаче появится радио.

### Повторы
По умолчанию — полный кадр с частотой 3/с (так сделано в README); стандартный NEC-повтор — опция. Оба вида реализуются здесь, выбор пока константой.

## Risks / Trade-offs

- [Эмуляция 52810 на DK не совпадает с реальным чипом по PWM/таймингам] → тайминги пересняты на своей плате в `add-board-hardware`.
- [Проектор не понимает «полный кадр» как повтор] → есть режим стандартного NEC-повтора.
