# Design

## Context

Исходные материалы — в корне репозитория (`README.md`, `schematic.*`, `sim*.py`). Кода нет. МК — WCH CH592F (решение владельца 25.11.2026 вместо nRF52810: $0,43–0,83 против $3,62, на складе JLCPCB; даташит V1.7 сверен). Отладка — на отладочная плата CH592F (WeAct WCH-BLE-Core или WCH EVT). Требования — `specs/ir-transmit/spec.md`.

## Goals / Non-Goals

**Goals:**
- Модуль NEC, покрытый unit-тестами без железа, и проверенный приборами вывод на отладочной плате.

**Non-Goals:**
- Хранение настроек, BLE, управление питанием, своя плата — это следующие задачи.
- Протоколы кроме NEC.

## Decisions

### Прошивка: SDK WCH + RISC-V GCC
Официальный SDK `openwch/ch592` (драйверы периферии открыты, BLE-стек — закрытая библиотека WCH). Сборка через Makefile и RISC-V GCC без MounRiver Studio — по образцу `cjacker/ch592evt_gcc_makefile`, чтобы собирать на Mac (гипотеза: на Mac не проверено — первая задача это и проверит). Прошивка — встроенным загрузчиком по USB/UART (вывод BOOT), отладка — 2-проводным интерфейсом через WCH-LinkE. Альтернатива — MounRiver Studio: официальная среда, но привязывает к IDE. Zephyr для CH592, по-видимому, нет (гипотеза).

### Кодирование отдельно от вывода
Чистая функция «адрес, команда, тип кадра → массив длительностей импульс/пауза» тестируется обычными unit-тестами на хосте (GCC/clang на Mac), без железа. Вывод — отдельный модуль. Так тайминги проверяются тестом, а не только осциллографом.

### Вывод: PWM-несущая + таймер огибающей
Несущая 38 кГц, скважность 1/3 — аппаратный PWM CH592 (26-битные каналы таймеров или 8/16-битные PWM4–11). Огибающая NEC — включение/выключение выхода PWM по прерываниям таймера (TMRx) по массиву длительностей. Риск — джиттер от прерываний BLE-стека в режиме настройки (кнопка «Отправить A/B»): на время кадра приоритет таймера выше, допуск ±5 % проверяется анализатором. Альтернатива — дёргать GPIO программно: хуже по джиттеру.

### Повторы
По умолчанию — полный кадр с частотой 3/с (так сделано в README); стандартный NEC-повтор — опция. Оба вида реализуются здесь, выбор пока константой.

## Risks / Trade-offs

- [Отладочная плата отличается от нашей по кварцу и разводке] → тайминги пересняты на своей плате в `add-board-hardware`.
- [Проектор не понимает «полный кадр» как повтор] → есть режим стандартного NEC-повтора.
