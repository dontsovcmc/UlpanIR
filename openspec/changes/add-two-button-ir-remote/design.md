# Design

## Context

Исходные материалы — в корне репозитория: `README.md` (решения, ссылки, расчёты), `schematic.png/svg` (схема v5: защёлка, ИК-каскад, JP1; блок МК — заглушка), `BOM_MCU_nRF52810_QCAA.csv`, `pcb_top_view.png`, модель брелока `fob_model_stl.zip`, расчёт ИК-каскада `sim.py`, `sim2.py`, `sim_burst.json`. Кода прошивки, проекта платы и страницы пока нет. Требования — в `specs/`.

Ограничения: CR2032 (пики выше ~30 мА снижают ёмкость), nRF52810 (192 КБ флеша, 24 КБ ОЗУ, у Nordic нет своего dev-kit — эмуляция на nRF52 DK), сборка на JLCPCB, первая прошивка — ESP32 по SWD.

## Goals / Non-Goals

**Goals:**
- Один прототип, проверенный замерами: ток покоя, бросок, ток на кадр, дальность.
- Прошивка и страница, которые можно отлаживать на nRF52 DK до прихода плат.

**Non-Goals:**
- Обучение от родного пульта, протоколы кроме NEC.
- OTA-обновление прошивки по BLE (прошивка только по SWD).
- Серийное производство, сертификация, свой корпус (используется донор).
- Защита настроек паролем или сопряжением BLE.

## Decisions

### Питание: мягкая защёлка вместо глубокого сна
Кнопки через диоды открывают P-FET Q1, МК удерживает его через N-FET Q2 и снимает питание сам. Альтернатива — постоянное питание и System OFF nRF52810 (~0,3–0,5 мкА по даташиту, гипотеза: не сверено) — проще схемотехнически, но схема с защёлкой уже нарисована и даёт нулевой ток покоя без зависимости от прошивки. Плавный старт Q1 (Rg 100 кОм + Cm 33 нФ) ограничивает бросок на ёмкость VDD. Схема не проверена на макете — первый пункт проверки.

Чтение кнопок: каждая кнопка, кроме диода в затвор Q1, заведена на свой GPIO, поэтому МК после старта знает, какие кнопки нажаты, и отличает «обе 2 с» от одной.

### Прошивка: nRF Connect SDK / Zephyr
Цель `nrf52dk/nrf52810` позволяет отлаживать на nRF52 DK. BLE — стек SoftDevice Controller из NCS. Альтернатива — голый nrfx + SoftDevice S112: меньше кода, но ручная работа с флешем и BLE; выигрыш в размере не нужен — 192 КБ хватает.

Поток работы: старт → удержать питание → прочитать кнопки и напряжение батарейки → если < 2,4 В — выключиться → если обе кнопки держатся ≥ 2 с — режим настройки → иначе отправка кода с повторами, пока кнопка нажата → снять питание.

### ИК: аппаратный PWM + таймер
Несущая 38 кГц со скважностью 1/3 — аппаратный PWM (у nRF52810 есть). Огибающая NEC — последовательность «включить/выключить несущую» из буфера длительностей через PWM в режиме последовательности (EasyDMA), без участия ЦП. Альтернатива — дёргать GPIO по таймеру: проще, но джиттер от BLE-прерываний в режиме настройки (тест кода со страницы).

### Настройки: один блок в NVS (Zephyr settings)
Все настройки — одна запись фиксированного формата с номером версии и CRC. NVS пишет запись атомарно, поэтому прерванная запись оставляет прежний блок целиком (требование «не смесь»). Альтернатива — отдельная запись на поле: проще менять, но теряется атомарность.

Формат блока v1 (little-endian): `version u8`, затем для A и B: `flags u8` (бит 0 — назначено, бит 1 — 16-битный адрес), `address u16`, `command u8`; затем `repeat_hz u8`, `repeat_mode u8` (0 — полный кадр, 1 — NEC-повтор).

### BLE: свой GATT-сервис
Один 128-битный сервис с характеристиками: `config` (чтение/запись, блок настроек целиком), `status` (чтение: версия прошивки, напряжение батарейки в мВ), `test` (запись: 0 — отправить A, 1 — отправить B, кодом из последнего записанного или переданного блока). Ошибки валидации — ATT-ошибка из диапазона приложения, страница переводит её в текст. UUID генерируются один раз и фиксируются в `firmware/` и `web/`. Альтернатива — Nordic UART Service с текстовыми командами: гибче, но нужен парсер в прошивке и протокол поверх.

Сопряжения нет (Non-Goal): окно 60 с только после физического удержания обеих кнопок — этого достаточно для пульта проектора.

### Страница: один статический HTML без сборки
`web/index.html` с встроенным JS, публикация на GitHub Pages (HTTPS есть). Поля: адрес (hex), 16-битный адрес (галка), команда (hex), частота, вид повтора; кнопки «Подключить», «Прочитать», «Записать», «Отправить A/B». Предварительный просмотр байтов кадра NEC рядом с полями. Альтернатива — фреймворк со сборкой: не нужна для одной формы.

### Плата: EasyEDA Pro → JLCPCB
МК — из референса Nordic (или импорт готового проекта из README, раздел 3), остальное — по `schematic.png`. Две стороны меди, земляной полигон, чистая зона под антенной. Светодиоды — у торца, обращённого вперёд. Если всё помещается на одну сторону — Economic PCBA.

## Risks / Trade-offs

- [Защёлка не держит или не отпускает при 2 В] → макет на отладочной плате и nRF52 DK до заказа; запасной путь — постоянное питание + System OFF (потребует правки спецификации тока покоя).
- [Ток двух LED > 30 мА из CR2032, Vmin ≈ 1,72 В на севшей батарейке] → по умолчанию JP1 разомкнута; при необходимости RL = 39 Ом; замер на реальной батарейке.
- [Коды Optoma X341 не подтверждены] → не блокирует: коды задаются на странице; взять из PDF руководства или снять приёмником TSOP + логическим анализатором.
- [Антенна в корпусе донора расстроена] → строгий референс, проверка дальности BLE в корпусе (спецификация board-hardware).
- [ESP32_nRF52_SWD не поддерживает nRF52810 явно] → проверить на первой плате; запас — OpenOCD через ST-Link.
- [Время старта МК + плавный старт > 50 мс до первого импульса] → замер; уменьшить Cm, если не укладываемся.

## Open Questions

- Точные NEC-коды Вкл/Выкл Optoma X341 — нужны только для первой проверки, в прошивку не зашиваются.
- Габариты корпуса-донора и положение толкателей — замер штангенциркулем перед разводкой контура.
- Нужен ли второй светодиод вообще — решается замером дальности с одним.
